# Repository maintenance and publishing

This cleanup preserves the current application layout. Entry points resolve paths
relative to the project root, and regression tests consume saved images under
`development/`. Moving these files would require a separate compatibility change.
No application code, stage definitions, dependencies, launchers, account settings,
or active runtime files were changed. No existing files were moved or deleted.

Created `.gitattributes` and this document; expanded `.gitignore`; rewrote the root
`README.md`; added current-scope notes to `MANAGER.md` and `game_library/README.md`.
All other documentation remains in place. Generated artifacts and uncertain files
were preserved locally rather than deleted.

## Fresh-clone data and portability

Use the root README for a new environment. Do not run installation or library
rebuild commands against an active farming installation. The library database has
user annotations and SQLite sidecars; copying the main database alone while it is
open is not a reliable backup. Its files and all downloaded assets remain untouched.

A new clone intentionally has no library cache. To populate a separate, inactive
installation after dependency setup, run from its root:

```powershell
& .\game_library\run.ps1 resume -PythonPath "$PWD\.venv\Scripts\python.exe"
```

This downloads public reference data and builds the local library. It depends on
upstream availability. The existing recognition calibration is tied to the exact
library database SHA-256. A rebuilt database may not match and automatic calibration
will then be disabled; matching can report unknown identities. Revalidate calibration
for that library before relying on calibrated loot recognition. Cleanup did not
rebuild the database or change calibration to suppress this guard.

Absolute `D:\NBR` paths in historical evidence, labeled ground truth and alert text,
plus fixed BlueStacks paths, acc1 identity/port assumptions and 900 × 1600 resolution,
remain portability constraints. No generic account configuration layer was added.
Test fixtures and templates are retained at their original paths; generated local
reports and live screenshots remain private by default.

## Git and security review

The root had no Git repository. It is prepared as a separate repository on `main`.
The clean nested `NBR-AM` repository already contained an initial commit and only
`.gitattributes`; its history and configuration remain untouched. Root preparation
does not stage files, create commits, add remotes or publish anything.

`.gitignore` excludes runtime, all virtual environments, process records, local
secrets, downloaded data and generated evidence. It deliberately retains required
PNG fixtures, templates, stage JSON and `item_recognition/reports/ground_truth.json`.
`.gitattributes` normalizes text, uses CRLF for Windows launch scripts and treats
images/databases as binary. It does not rewrite existing working files.

The source review found no confirmed embedded credentials. Local machine paths,
the public loopback ADB address, app package and acc1 label are implementation
defaults. Live process/account evidence and library annotations are excluded.
Review the prospective file list again before publishing, especially retained
screenshots and historical reports. Asset redistribution rights and the project
license remain decisions for the owner; no license grant was invented.

## First commit and push (owner action)

Create an empty GitHub repository first and substitute its URL below. Review the
file list before staging. These commands are provided for later use and were not
executed during cleanup:

```powershell
Set-Location D:\NBR
git status --short --untracked-files=all
git ls-files --others --exclude-standard
git add -- .
git diff --cached --stat
git diff --cached --check
git commit -m "Prepare NBR automation manager repository"
git remote add origin https://github.com/YOUR-ACCOUNT/YOUR-REPOSITORY.git
git push -u origin main
```

Configure Git author name/email locally before committing if Git requests them.
If the intended GitHub repository already has commits, reconcile that history
before pushing; do not force-push over it. Check for secrets and private screenshots
in the staged diff before committing. The ignored nested repository is independent;
these commands do not publish its history.

## Validation record

Cleanup validation is limited to syntax, isolated mocked tests, static references,
documentation links and prospective Git files. Live Start/Stop, status/device
probing, ADB, game interaction and library rebuilding are intentionally unverified
in this task.

On 2026-10-13, 247 isolated tests passed with no failures or errors: 159 root tests,
37 library tests and 51 recognition tests. All 48 existing Python sources parsed
successfully. The existing `.venv` interpreter was used read-only with `-B` and
offscreen Qt. In-memory audit guards rejected workspace writes, project database
connections, real subprocess launches and unexpected network connections. Devices,
process checks and OCR were mocked. Library HTTP tests used only a newly created
ephemeral loopback server and temporary database; crawler requests were mocked.

Three tests were omitted to avoid real subprocess or installed-library access:

- `test_disposable_process_exit_persists_ended_session_without_farming_access`
- `test_real_recognizer_integration_is_readonly_and_uses_saved_evidence`
- `test_real_nearest_sakura_five_star_form_is_not_accepted_as_four_star`

The full README test commands include those integrations and should be used on an
idle checkout. Cleanup used a guarded subset instead. No dependencies were installed
or upgraded and no bytecode files were written.

Final static checks passed: all 12 prospective JSON files parsed, 156 stage/catalog
template references resolved, 14 links in the updated documentation resolved, all
four PowerShell scripts parsed, and 33 include/exclude checks matched expectations.
SHA-256 comparisons confirmed all 16 protected core files, launchers, requirement
files, stage definitions and pattern catalogs were unchanged. The prospective
file scan found no credential-pattern matches; this is not a visual privacy audit
of every retained screenshot.

The root index is empty, has no commits or remotes, and uses `main`; the nested
repository remains clean at its original initial commit. There are 455 prospective
files totaling about 356 MiB (largest file about 2.77 MiB). Retained image fixtures
make this a substantial initial checkout. Reducing them is deferred until fixture
coverage and privacy have been reviewed; none was deleted for size alone.
